# dotnet new  vs maven-archetype

Yes, `dotnet new` is conceptually identical to Maven Archetypes (like `maven-archetype-quickstart` or `maven-archetype-webapp`). They serve the exact same purpose: scaffolding a fully functional, structured project from a pre-defined template. \[1, 2, 3, 4, 5]

However, the .NET ecosystem handles this in a cleaner, faster, and more modern way than Maven.

## The Key Differences

|Feature|Maven (`mvn archetype:generate`)|.NET CLI (`dotnet new`)|
|---|---|---|
|Speed|Slow; routinely downloads plugins and scans catalogs.|Near instant; engine is baked right into the standard SDK.|
|Configuration|Generates a verbose `pom.xml`.|Generates a minimal `<ProjectName>.csproj`.|
|Complexity|Prompts for `groupId`, `artifactId`, and `version` interactively.|Infers your project name from the folder name automatically.|

# 🛠️ .NET CLI: dotnet new

The **`dotnet new`** command creates a new .NET project, configuration file, or solution based on a specified template.
[Ref](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-new)

`dotnet new <TEMPLATE>`

## 🚀 Common Project Templates

Run the command followed by the template's short name:

- `dotnet new console` — Console Application
- `dotnet new webapi` — ASP.NET Core Web API
- `dotnet new mvc` — ASP.NET Core MVC Web App
- `dotnet new blazor` — Blazor Web App
- `dotnet new classlib` — Class Library
- `dotnet new xunit` — xUnit Test Project
- `dotnet new sln` — Solution File

---

## ⚙️ Useful Options & Flags

Append these flags to modify project creation:

- `-n <NAME>` — Sets the output name of the project.
- `-o <DIRECTORY>` — Sets the target location directory.
- `-f <FRAMEWORK>` — Targets a specific framework (e.g., `net8.0`, `net10.0`).

> [!TIP] Example Usage
> `dotnet new webapi -n MyBillingApi -o ./src/BillingApi`

---

## 🛠️ Template Management

Use these subcommands to manage your local and remote templates:

- `dotnet new list` — Lists all installed templates.
- `dotnet new search <NAME>` — Searches NuGet.org for third-party templates.
- `dotnet new install <PACKAGE>` — Installs a template via NuGet ID or path.
- `dotnet new uninstall <PACKAGE>` — Removes an installed template package.
- `dotnet new update` — Updates all installed template packages.

---

## ❓ Help

- `dotnet new -h` — Displays help documentation in the terminal.

# How to use `dotnet new` in your Blank Codespace

When you fire up your blank Codespace environment, run these commands inside the terminal to create your application. \[6]

## 1. Console Application (Equivalent to

`maven-archetype-quickstart`) \[7]

Creates a lightweight, single-file "Hello World" executable. \[8]

```bash
dotnet new console -o MyConsoleApp
```

## 2. Web API (Equivalent to a modern REST `maven-archetype-webapp`) \[7]

Creates a foundational REST API endpoint structure with setup files. \[9, 10]

```bash
dotnet new webapi -o MyWebApi
```

## 3. Class Library (Equivalent to a standard Java JAR project) \[7]

Creates a reusable library containing core business logic, but no entry point. \[11]

```bash
dotnet new classlib -o MyLibrary
```

_Note: The `-o` flag stands for output. It automatically creates a new folder with that name and drops the files cleanly inside._ \[12, 13]

## Useful Commands to Explore

- See everything available: Run `dotnet new list` to see all built-in templates (Blazor, MVC, xUnit testing, etc.).
- Run the application: `cd` into your new folder and type `dotnet run`. It handles the building and dependency restoration automatically. \[8, 14]

# -o flag

If you omit the `-o` (output) flag, `dotnet new` will ==generate all the project files directly inside your current working directory==.

## The Problem it Causes

It will use your current folder name as the project name and `.csproj` file name. If you run `dotnet new console` while standing in your root directory (like `/workspaces/codespaces-blank`), it will dump files like `Program.cs` and `codespaces-blank.csproj` right there, mixing them up with your `.devcontainer` and `.gitignore` files.

## How to use `dotnet new` without the `-o` flag safely

If you prefer not to use the flag, you must manually create and step into a new folder first using standard terminal commands:

```bash
mkdir MyConsoleApp
cd MyConsoleApp
dotnet new console
```

This achieves the exact same clean separation as running `dotnet new console -o MyConsoleApp` from the root directory.

## How to Clean Up if You Accidentally Forgot the Flag

If you already ran the command in your root folder by mistake and everything is messy, you can undo it instantly by running:

```bash
dotnet new console --force --dry-run
```

_(This won't delete them, but it lists exactly which files it created so you know which ones to manually delete)._

# 📦 .NET Solutions

A **solution (`.sln`)** in .NET is a container file used to organize and manage one or more related projects. It contains no source code itself, serving instead as a structural blueprint that defines project relationships, build configurations, and dependencies for an entire application ecosystem.

## 💻 Common Solution Commands

Manage your .NET ecosystem from the terminal using these core commands:

- `dotnet new sln` — Creates a blank solution matching the folder name.
- `dotnet new sln -n <NAME>` — Creates a blank solution with a custom name.
- `dotnet sln add <PROJECT_PATH>` — Adds an existing project (`.csproj`) to the solution.
- `dotnet sln remove <PROJECT_PATH>` — Disconnects a project from the solution (files remain safe).
- `dotnet sln list` — Lists all projects currently tied to the solution.
- `dotnet build` — Compiles all projects listed in the solution at once.

## ⚖️ .NET Solution vs. Maven Submodule

If you are coming from the Java ecosystem, a .NET Solution serves a similar organizational purpose to a Maven Multi-Module project, but their underlying architectures handle dependencies and builds differently.

| Feature | 🔷 .NET Solution (`.sln`) | 🍃 Maven Multi-Module (`pom.xml`) |
| :--- | :--- | :--- |
| **File Type** | Metadata / Plain Text (Unique syntax or JSON-like in modern .NET) | XML (`pom.xml` with `<modules>` tag) |
| **Relationship** | **Top-Down Link**: The solution points to projects; projects do not know they belong to a solution. | **Two-Way Hierarchy**: Parent lists children; child modules must explicitly declare their `<parent>`. |
| **Code Container** | No. Contains zero source code, configurations, or properties. | Yes. The parent POM can host shared dependencies, plugins, and properties. |
| **Project Types** | Can group completely unrelated projects together in one view. | Designed for tightly coupled modules sharing a lifecycle and version. |
| **Build Execution** | Building the `.sln` triggers sequential or parallel builds of listed projects. | Building the parent POM builds all modules based on a calculated dependency graph. |

> [!NOTE] Key Conceptual Difference
> In **Maven**, a submodule is rigidly bound to its parent POM for inheritance (sharing dependencies and versions). In **.NET**, a project is entirely independent; the solution file is just a convenient visual and structural grouping tool for your IDE or CLI.

## 🛠️ Multi-Project Initialization Script

Copy and run this script in your terminal to instantly generate a standard, clean multi-project architecture:

```bash
# 1. Create a root directory and move into it
mkdir MyEnterpriseApp && cd MyEnterpriseApp

# 2. Initialize a blank solution file
dotnet new sln

# 3. Create structured folders for source code and testing
mkdir src
mkdir test

# 4. Generate the projects
dotnet new webapi -o src/MyWebApi
dotnet new classlib -o src/MyCoreLibrary
dotnet new xunit -o test/MyTests

# 5. Bind the projects to your solution
dotnet sln add src/MyWebApi/MyWebApi.csproj
dotnet sln add src/MyCoreLibrary/MyCoreLibrary.csproj
dotnet sln add test/MyTests/MyTests.csproj

# 6. Link dependencies (WebAPI references Core Library)
dotnet add src/MyWebApi/MyWebApi.csproj reference src/MyCoreLibrary/MyCoreLibrary.csproj

# 7. Verify and build the entire ecosystem
dotnet build
```
